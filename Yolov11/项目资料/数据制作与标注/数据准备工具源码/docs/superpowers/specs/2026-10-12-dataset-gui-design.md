# 数据集处理 GUI 设计方案

## 目标

在 `D:\make_dataset` 中开发一个中文 PyQt5 桌面应用，用于视频导入和抽帧、带标签数据集划分、图片抽样划分。标注和模型训练作为未接入模块显示，并预留独立接口；本阶段不实现标注算法或训练流程。

应用默认不得修改现有的 `images/`、`labels/`、`iceice/`、`xz_dataset/`。每次导入视频创建独立项目目录。`D:\yolov11` 中的 YOLO 工程保持独立。

## 已确认的用户选择

- 使用当前 Python 环境已有的 PyQt5 和 OpenCV。
- 每次导入创建一个独立项目；一次导入可以选择多个视频。
- 原视频只记录路径，不复制到项目目录。
- 抽帧频率可配置，默认每秒 2 帧。
- 标注和训练在主界面显示为“未接入”，只预留模块接口，不实现功能。
- 将现有带标签数据集划分和图片抽样划分作为两个独立页面加入 GUI。
- `make_xz.py` 保持现有行为：只处理图片，不复制标签。
- 不合并或重新划分现有数据集。

## 用户操作流程

1. 新建项目，填写项目名称并选择一个或多个视频。
2. 应用在 `projects/` 下创建唯一项目目录，记录视频绝对路径，并显示视频信息和预览。
3. 设置目标 FPS（默认 2）并开始抽帧。每次抽帧写入独立运行目录，按视频分组；再次抽帧不会覆盖之前的结果。
4. 在缩略图区域查看抽出的图片、打开大图，或打开图片所在目录，用其他工具手动标注。
5. 在“图片和标签划分”页选择图片目录、标签目录和输出目录，按默认 70/20/10 复制为训练集、验证集、测试集。在“图片抽样划分”页选择图片目录，默认抽样 20%，再按 70/30 分成训练集和验证集。两个页面都只复制源文件，不移动源文件。
6. “标注”和“训练”入口显示为未接入，不启动标注工具、不推理生成标签，也不启动 YOLO 训练。

## 项目目录结构

```text
projects/
  <项目 ID>-<项目名称>/
    project.json
    extraction_runs/
      <运行 ID>/
        frames/
          <视频 ID>-<视频名称>/
            <视频名称>_00001.jpg
    datasets/
      labeled-split-<运行 ID>/
        images/{train,val,test}/
        labels/{train,val,test}/
      image-sample-<运行 ID>/
        images/{train,val}/
```

项目元数据记录格式版本、项目标识、源视频路径和基本文件信息、目标 FPS、各次抽帧的状态与图片数量，以及输出路径。原视频不会复制到项目中。重新打开项目时，如果原视频路径失效，应用会将视频标记为不可用，并允许用户重新选择该视频路径后再抽帧。

每次抽帧或划分操作使用新的运行目录。不会覆盖已有输出。取消操作后保留已经生成的文件，并将运行状态记为“已取消”；再次启动时创建新运行目录，不向未完成的目录追加内容。

## 界面与模块

- `app.py`：启动应用并创建主窗口。
- `dataset_tool/ui/`：主窗口、项目/视频页面、带标签划分页、图片抽样页、缩略图组件和占位页面。
- `dataset_tool/core/`：项目模型、路径管理、JSON 持久化和运行状态管理；不依赖界面控件。
- `dataset_tool/services/`：不依赖 UI 的视频抽帧、图片/标签配对划分、图片抽样逻辑。服务接收路径和参数，并返回结构化结果。
- `dataset_tool/workers/`：通过 `QThread` 调用耗时服务，并发出进度、完成、取消和错误信号。界面控件本身不解码视频或复制数据集文件。
- `dataset_tool/modules/`：定义简单的页面/模块接口和注册表。视频抽帧及两个划分模块可用；标注和训练作为不可用占位模块。这是应用内部的模块接口，不搭建动态插件系统。
- 现有 `extract.py`、`split.py`、`make_xz.py` 保留命令行入口，改为调用与 GUI 共用的服务函数，避免维护两份实现。

### 服务接口约定

- **视频抽帧服务**：接收视频路径、输出路径、目标 FPS、进度回调和取消回调。对于固定帧率视频，沿用现有脚本的取帧规则：`frame_interval = max(1, int(source_fps / target_fps))`，从第 0 帧开始。由于视频帧是离散的，实际输出频率是近似值；目标 FPS 高于视频源 FPS 时保存每一帧。返回帧数及视频信息或结构化错误；成功、失败、取消时都释放 OpenCV 资源。
- **带标签划分服务**：接收图片目录、标签目录、输出目录、训练/验证/测试比例和随机种子。只复制扩展名为小写 `.jpg` 且存在同名 `.txt` 的文件；缺少标签时报告并跳过；空标签文件仍视为有效配对。默认比例 70/20/10，随机种子 42。比例必须非负且总和大于 0；若总和不等于 1，则归一化到 1，并在界面提示调整后的比例。
- **图片抽样服务**：接收图片目录、输出目录、抽样比例、训练集比例和随机种子。默认抽样 20%，再按 70/30 划分训练集/验证集，随机种子 42。只复制图片，并明确提示没有复制标签。
- 所有服务在写入前检查输出目录；目录非空时拒绝运行。服务不得移动或修改源文件。

## 界面行为与错误处理

- 主窗口左侧为项目/视频列表，中间为视频预览，右侧为抽帧设置和进度，下方为抽出图片的缩略图区域。独立导航入口打开两个数据划分页面和两个未接入占位页面。
- 视频解码和文件复制在后台线程执行，界面保持响应。用户可取消运行；已完成的输出会保留，运行状态会显示出来。
- 无效 FPS、目录不存在、视频格式不支持或视频无法读取、缺少标签、输入为空、输出目录冲突、写入失败和用户取消，都要以清晰中文提示。视频处理失败不能被误报为成功。
- 划分页让用户明确选择输入目录和输出目录。默认输出放在当前项目下新建的运行目录；如果用户选择了非空目录，应用拒绝写入。
- 作为输入选择现有数据目录时，应用不修改这些目录。非空目录不可作为输出目标。

## 验收标准

- 使用临时测试目录和短小的生成或复制视频，不对现有数据目录运行处理操作。
- 验证 2 FPS 及另一个频率下的抽帧数量、命名、进度更新、取消状态，以及重复抽帧写入新运行目录。
- 验证视频无法读取和 FPS 无效时的错误提示、OpenCV 资源释放，以及对非空输出目录的保护。
- 验证带标签划分的图片/标签配对、比例、固定随机种子、缺标签提示和源文件保留。
- 验证图片抽样比例为 20%、抽样结果按 70/30 划分、只复制图片且保留源文件。
- 手动启动 PyQt5 应用，检查项目创建、多视频导入、预览、各个页面、占位入口、进度和取消操作。
- 验收结束后确认现有数据目录中的文件数量和代表性文件哈希没有变化。

## 假设与范围外事项

- 应用面向当前 Windows/Python 环境，通过 `python app.py` 启动；本阶段不打包安装程序。
- 项目目录默认位于 `D:\make_dataset\projects`，可在应用设置中修改根目录。
- 手动标注、自动/半自动标注、YOLO 训练、推理、数据集合并和项目同步不在本阶段实现。
- 本文档是待审阅的设计。用户审阅并确认书面设计、再确认实施计划后，才开始实现。

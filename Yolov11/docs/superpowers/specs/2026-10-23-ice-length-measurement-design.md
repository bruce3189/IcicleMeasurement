# 冰凌两点长度测量模块设计

## 目标

把 CSDN 文章中的 YOLO Pose 与 D435i 测距流程改造成可在本项目使用的模块化工作流。当前阶段使用两点关键点冰凌数据集，在本地 CPU 上训练和推理；D435i 不在手边时，用明确标记的理想深度模拟值走通几何计算链路。相机回来后可以换成真实深度来源。

每个冰凌实例的关键点约定为：

- `tip`：冰凌尖端。
- `root`：冰凌与屋檐、支撑物或主体连接处。

系统测量的是两点在三维空间中的欧氏直线距离。弯曲冰凌的这条弦长小于沿冰凌中心线的弧长。

## 已确认的约束

- 数据集将由用户稍后准备，包含每个冰凌的框、tip 和 root 两个关键点。
- 训练与推理在本机执行，训练设备为 CPU。
- 相机暂不在手边，当前使用理想模拟深度；所有结果必须标记为模拟值。
- RealSense 深度支持应当是可选模块，不能成为模拟流程的依赖。
- 不覆盖或删除已有权重、数据快照、`runs_pose` 实验记录和旧推理脚本。
- 不训练实例分割，也不声称 tip 会自动修正检测框。

## 方案选择

### 方案 A：单文件脚本

将训练、推理、深度读取、三维几何和绘图都放在一个脚本中。启动快，但模拟深度与 RealSense API 耦合，后续替换数据源和排错较困难。

### 方案 B：模块化流水线（推荐）

分开训练入口、Pose 推理、深度来源、几何计算和结果输出。模拟深度与真实 RealSense 实现同一接口；测量核心无需知道深度来自哪里。

### 方案 C：重构为 GUI 或 ROS 应用

适合后续部署或机器人集成，但当前没有相机和两点数据集，超出验证长度测量算法所需范围。

采用方案 B。

## 模块与接口

建议新增独立目录 `ice_length/`，现有脚本保持不动。

### `train_pose.py`

- 接受数据集 YAML、预训练 Pose 权重、输出目录和训练参数。
- 使用 `device=cpu`、`workers=0`、`cache=False`；训练参数可以从命令行覆盖。
- 数据集输入按标准 YOLO Pose 结构读取。收到实际数据集后先检查类别、`kpt_shape: [2, 3]`、框与关键点的实例对应和 train/val/test 路径，再启动训练。
- 默认优先使用项目已有的本地 Pose 权重；若权重与两点输出头不兼容，先做小规模兼容性检查并报告，不擅自下载或安装模型。
- 训练集用于梯度更新，验证集用于选择权重，测试集只用于最终报告。

### `pose_inference.py`

- 加载指定 Pose 权重，对单图、目录或视频逐帧推理。
- 读取每个实例的框、两个关键点及置信度，并保留原图像素坐标。
- 关键点通过同一个检测实例索引绑定，不按检测框面积、列表顺序或邻近关系重新配对。
- 使用流式结果处理，避免将全部图片结果堆在内存中。

### `depth_source.py`

提供统一的 `DepthProvider` 接口，输入原图像素坐标，返回米制深度或明确的无效状态。

- `IdealConstantDepthProvider`：返回配置中的固定深度值，并携带 `simulated=true` 标记。配置提供 `fx`、`fy`、`cx`、`cy` 和深度 `Z`。
- `RealSenseDepthProvider`：可选实现，运行时才导入 `pyrealsense2`。读取 RGB 与深度帧、对齐坐标并取得与对齐图像相匹配的相机内参。点处深度无效时，在可配置的小邻域内取有效深度中位数；仍无有效值则报告该实例不可测，不用模拟值替代。
- 目前环境未安装 `pyrealsense2`，因此模拟模式不得导入或要求该依赖。

### `geometry.py`

- 使用针孔相机反投影：`X=(u-cx)Z/fx`，`Y=(v-cy)Z/fy`，`Z=Z`。
- 长度按 `sqrt((Xt-Xr)^2 + (Yt-Yr)^2 + (Zt-Zr)^2)` 计算。
- 检查焦距、像素坐标、深度为正且有限；无效输入返回可读错误，不输出伪造长度。

### `measure.py` 与配置

- 串联 Pose 推理、深度查询、反投影、长度计算和输出。
- 支持单张图片、图片目录和视频流；逐帧写结果。
- 模拟/真实模式由配置或命令行选择，不能静默切换。

## 数据流

```text
RGB 图像 / 视频
        ↓
YOLO Pose：每个实例输出 box、tip、root
        ↓
DepthProvider：在 tip/root 像素位置查询深度
        ↓
针孔反投影：像素坐标 + 深度 + 相机内参 → XYZ
        ↓
三维欧氏距离
        ↓
标注图 + CSV/JSON 结果
```

## 理想深度模拟的含义与限制

模拟模式假设 tip 和 root 都位于配置的同一个深度平面 `Z`。它用于核对坐标映射、反投影、距离计算、实例关联和结果导出是否连通。此假设不等价于真实冰凌的深度形状，也不能证明模型关键点准确或测量真实尺寸准确。

所有模拟输出应显示 `SIMULATED`，并在 CSV/JSON 中写入深度模式和相机内参。真实模式输出不得带该标记。

## 输出

- 每张图片或视频帧的可视化结果：实例框、tip、root、两点连线、长度和 `SIMULATED` 状态。
- CSV/JSON：来源帧、实例索引、框、两个关键点像素坐标与置信度、两点深度、三维坐标、长度、深度模式、无效原因。
- 新结果写入独立运行目录，例如 `runs_pose/ice_length/<run_name>/`，不覆盖旧实验。
- 提供中文 README，说明模块输入输出、参数、运行命令和如何解释模拟值。

## 评估与成功标准

- 新数据集到达后，先做标签与 split 审核；未确认实例对应关系前不训练。
- CPU 训练通过短轮次启动检查后，再按用户确认的参数训练；报告实际训练时间和资源使用情况。
- 最终权重在独立 test 集上评估；报告框指标、tip/root 的原图像素误差、漏检/多检和逐实例预测图。
- 没有实测深度或实物长度真值时，只报告模拟几何链路结果，不报告真实测量精度。
- 若用户提供已知实物长度，可另行比较测量误差；这是后续接入实测数据后的验收项。

## 错误处理

- 数据集类别数或关键点形状不匹配时，在训练开始前停止并指出具体配置项。
- 缺少某个实例关键点时按数据格式可见性规则处理；不把缺失点当作图像左上角 `(0, 0)`。
- 模型未检测到实例、关键点置信度过低或真实深度无效时，保留检测记录并输出不可测原因，不输出长度数值。
- 某帧处理失败时记录帧名与错误，继续处理后续帧。

## 范围外

- 改写现有 `mypredict.py`、检测后处理和已有实验代码。
- 删除旧数据、权重或运行目录。
- 实例分割、深度补全、相机标定工具或 GUI。
- 在没有 D435i 与实物尺寸真值时宣称真实测量精度。

## 环境注意事项

当前本机 `D:\318\envs\yolov11` 环境可见 CPU 版 PyTorch（2.0.0）和 Ultralytics（8.3.21），未检测到 CUDA 或 `pyrealsense2`。Ultralytics 导入时报告 Python 3.9 与其当前 Python 版本要求不匹配，并尝试写入用户级配置时被拒绝。实现阶段先做只读的运行兼容性确认；若训练环境确实不兼容，再明确指出所需环境变化，不静默安装或升级依赖。

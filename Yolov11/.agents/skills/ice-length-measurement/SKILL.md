# 冰凌两点长度测量

在 `D:\yolov11` 项目中实现或维护基于 YOLO Pose 的冰凌长度测量流程。当前任务设计与模块边界见 [冰凌两点长度测量模块设计](../../../docs/superpowers/specs/2026-10-23-ice-length-measurement-design.md)。先检查当前代码和数据集，再按用户当前请求推进；不要把“做技能”“看进度”等请求擅自扩大成训练或重构。

## 任务约定

- 每个冰凌实例使用一个检测框和两个关键点，顺序统一为 `tip`（尖端）、`root`（与屋檐、支撑物或主体连接处）。确认数据标注、数据转换和模型输出使用同一顺序。
- 目标长度是 tip 与 root 的三维欧氏直线距离，也就是弦长。弯曲冰凌的弧长可能更长；没有中心线建模时不要称为弧长。
- 当前训练和推理在本机 CPU 执行。训练参数显式使用 `device=cpu`、`workers=0`，并为实验写入新目录。
- D435i 暂不可用时，可用固定深度平面打通像素坐标、反投影、距离计算与结果导出。模拟值只能验证几何数据流，不能证明关键点精度、真实深度或实物测量精度。
- RealSense 支持保持可选。模拟模式不能导入或依赖 `pyrealsense2`。

## 工作方式

### 数据与训练

1. 找到用户指定的数据集；如果提到过 `C:\Users\Administrator\Desktop\冰凌训练集_232_20261023\`，先检查该路径是否仍存在，不要假设它是当前有效数据。
2. 训练前审核 YOLO Pose 数据 YAML、类别数、关键点形状（两点时应为 `kpt_shape: [2, 3]`）、标签解析、图像与标签对应、缺失点可见性编码、train/val/test 划分，以及每个框和两个点是否属于同一冰凌实例。发现对应关系或标签顺序不明确时先修正/报告，不开始训练。
3. 优先检查项目已有本地 Pose 权重与当前 Ultralytics 版本。确认权重的关键点输出头能适配两点任务；不兼容时先解释并提供最小兼容性检查，不静默下载权重、安装依赖或升级环境。
4. 训练集用于更新参数，验证集用于选权重，测试集只用于最终评估。报告实际训练设置和 CPU 训练时间；评估 tip/root 原图像素误差、检测指标、漏检/多检，并查看代表性预测图。

### Pose 推理与实例关联

- 每个模型结果中的框、tip、root 必须按同一个实例索引绑定。不可仅按框面积、输出顺序重排或最近邻把关键点跨实例配对。
- 保留关键点原图像素坐标和置信度；关键点置信度低、实例未检出或点坐标无效时，记录原因并将该实例标为不可测，不伪造坐标或长度。
- 对目录和视频逐帧处理，避免把整批预测累积在内存中；一帧失败时记录来源并继续处理后续帧。

### 深度与几何

将深度查询封装为统一接口，输入原图像素坐标，返回米制深度及来源/有效状态。

- **理想模拟模式：** 使用配置的 `fx`、`fy`、`cx`、`cy` 和固定 `Z`。输出图像明确显示 `SIMULATED`，CSV/JSON 写入 `depth_mode=simulated` 及相机参数。
- **RealSense 模式：** 运行时才导入 `pyrealsense2`；对齐彩色与深度坐标，并使用对齐图像对应的内参。像素深度无效时可在配置的小邻域取有效深度中位数；仍无效则输出不可测原因，严禁静默用模拟深度兜底。
- 针孔反投影：`X=(u-cx)Z/fx`、`Y=(v-cy)Z/fy`、`Z=Z`。长度为 `sqrt((Xt-Xr)^2 + (Yt-Yr)^2 + (Zt-Zr)^2)`。
- 检查内参、坐标、深度均为有限值且焦距和有效深度为正；无效输入返回可读错误，不输出长度。

### 结果和实验管理

- 可视化标出实例框、tip、root、连线、长度和深度模式；结果表记录图像/帧、实例索引、关键点坐标和置信度、深度、三维坐标、长度及无效原因。
- 新结果写入独立运行目录，例如 `runs_pose/ice_length/<run_name>/`。不得覆盖或删除已有权重、数据快照、`runs_pose` 记录及旧推理脚本（包括 `mypredict.py`、`mypredict_largest.py`）。
- 没有真实深度和实物长度真值时，只报告模拟几何链路是否正确，不报告真实尺寸精度。接入相机后仍需已知长度样本或其他真值来量化误差。
- 不把关键点检测说成分割；不声称 tip 会自动修正检测框。实例分割、GUI、相机标定工具和深度补全不属于默认范围，只有用户提出时才扩展。

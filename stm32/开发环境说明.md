## 路径与入口

- 工具根目录：`D:STM32Tools`；各工具的准确路径与版本记录在 `Configenvironment-status.json`。
- SDK：`D:STM32ToolsRepositorySTM32Cube_FW_F1_V1.8.7`。
- 独立验证工程：`D:STM32Workspaceenvironment-check`，与控制板业务固件分开。
- 双击 `D:STM32ToolsStart-Environment.cmd` 打开配置好的命令行；只影响该终端，不改全局 Python 或系统 PATH。
- 双击 `D:STM32ToolsBuild-Environment-Check.cmd` 构建最小验证工程。
- 双击 `D:STM32ToolsStart-Serial-Terminal.cmd` 使用项目专用 Tera Term 配置，COM口按实际设备选择。
- `D:STM32ToolsCheck-STLink.cmd` 只枚举下载器，不下载、擦除或改写选项字节。
- `D:STM32ToolsOpen-Environment-Check.cmd` 用已有 VS Code 打开验证工程；提供了 Ctrl+Shift+B 构建任务，**尚未验证图形界面实际触发**，也未安装 ST 的 VS Code 扩展来替代原计划。

在已打开的 cmd 中可执行：

```bat
call D:STM32ToolsSTM32-Environment.cmd
python -m serial.tools.list_ports
STM32_Programmer_CLI -l stlink
```

## 已完成的验证与限制

最小工程使用 STM32F103xB 设备定义、64KiB Flash、20KiB RAM、内部8MHz HSI，仅循环更新计数，不控制业务 GPIO。已生成 ELF、HEX、MAP；链接报告 Flash使用2244B、RAM使用1584B。

构建日志中有 newlib/nosys 未提供文件读写系统调用及旧版模板链接脚本 RWX 段的提示；该环境验证程序不使用文件I/O。这不是控制板成品固件，正式工程仍需按实际外设和生成器配置验证，不能据此声称板上程序已正常运行。完整日志在 `D:STM32ToolsLogshal-environment-build.txt`。

CubeProgrammer 实际输出 `No ST-Link detected!`。没有连接并读取到目标，也未擦写任何开发板。Python本地回环不等于外部UART或USB-TTL连线已经通过。

SDK原包自带示例和中间件，但验证工程只使用HAL/CMSIS，没有加入RTOS、网络或文件系统。官方下载辅助器只用于获取配套组件，构建入口直接调用固定版本GCC/CMake/Ninja，不依赖辅助器在线更新。

## 剩余安装步骤

从下面官方页面下载 **Windows x64** 安装包，放到 `D:STM32ToolsDownloads`：

1. [STM32CubeIDE](https://www.st.com/en/development-tools/stm32cubeide.html)，当前核对的稳定版2.2.0。
2. [经典 STM32CubeMX](https://www.st.com/en/development-tools/stm32cubemx.html)，选择支持STM32F103的6.x版本，不选CubeMX2。

取得安装包后继续：核对官方文件与签名、安装到工具目录、将CubeMX仓库指向已有F1包、关联.ioc、导入/生成最小工程并实际验证图形构建。此时再记录最终软件版本。需要登录或验证码时由本人完成该步骤。

CubeProgrammer图形版如需完整安装，也可从[官方页面](https://www.st.com/en/development-tools/stm32cubeprog.html)获取；当前命令行版已可用于后续下载与检测。

软件安装的系统提权不等于终端文件访问授权；如果驱动安装提示权限不足，需要在本机管理员安装流程中完成，不关闭驱动签名或其他系统保护。

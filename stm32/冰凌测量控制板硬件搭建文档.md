# 冰凌测量控制板（STM32 下位机）— 硬件搭建文档

> 2026-10-27 精简版。对应本目录《需求与现状清单》的 5 个保留模块。当前为面包板接线方案，已有 `firmware/` 可编译模块框架，尚无完整固件或实测报告；后续 PCB 使用排母插接现成核心板。

## 一、固定引脚表

使用 STM32F103C8T6 的默认引脚映射，本版不使用外设重映射。

| 模块 | 信号 | STM32 引脚 | 连接方式 |
| --- | --- | --- | --- |
| 模块1 UART | TX / RX | PA9 / PA10（USART1） | 接 PC 的 USB-TTL 或树莓派，二选一；115200 8N1 |
| 模块2 OLED | SCL / SDA | PB6 / PB7（I2C1） | 上拉到 3.3V，地址按实物确认 |
| 模块4 状态灯 | 绿 / 红 | PB8 / PB9 | 每颗串 220Ω 后接 LED 阳极，阴极接地，高电平亮 |
| 模块6 两键 | START / STOP | PB12 / PB13 | 内部上拉输入，按键另一端接地，按下为低 |
| 模块7 照明 | PWM | PA6（TIM3_CH1） | 经 470Ω 接 MOSFET 栅极 |
| 调试接口 | SWDIO / SWCLK | PA13 / PA14 | 保留给 ST-Link，不分配给外围模块 |

功能信号共占 9 个 GPIO，另有 2 个 SWD 引脚。原 PA4/PA5 光敏、PB5 蜂鸣器、PB14 第三键、PA8 复位及 PA2/PA3 调试串口不接线，也不要求在本版载板上预留相应接口。

## 二、先确定电源路径

面包板阶段以最小系统板 USB 口为唯一 5V 输入；板上 LDO 生成 3.3V。若从板上 5V 引脚给低功率 LED 取电，应先核对该板原理图或实测连通关系及允许电流，不能仅凭针脚文字认定 USB 5V 一定已引出。

```text
单一 5V 电源 ──USB──→ 最小系统板 ──板上LDO──→ 3.3V ──→ OLED/状态灯
                          │
                          └─经确认可取电的5V引脚──→ 低功率白光LED支路
所有模块 GND ───────────────────────────────────→ 公共地
```

如果该板无法按此路径给 LED 供电，应改成一只外部 5V 电源分别供核心板 5V 输入与 LED，同时断开核心板 USB 的供电路径；不能在不知道板内连线的情况下并联多个 5V 输入。

- USB-TTL 只接 TX/RX/GND，不把它的 5V、3.3V 输出并到电源轨。
- 树莓派独立供电，UART 接口只接 TX/RX/GND，不连接两块板的 5V/3.3V 电源输出。
- OLED 工作电压与上拉电压都核对为 3.3V；并联多个上拉前先检查现有电阻与波形，不用“通信不稳就再并4.7kΩ”代替排查。
- 上电前查短路，先测 5V/3.3V，再逐个接入负载；改变接线先断电。

### ST-Link 接法

| ST-Link 信号 | 核心板 |
| --- | --- |
| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND |
| VTref / VAPP（若该型号具有目标电压参考输入） | 接目标板 3.3V，按该下载器手册要求连接 |
| 3.3V / 5V 电源输出（若实物提供） | 本方案不用于给板供电，不与已有电源输出并联 |

原装 ST-LINK/V2 的 VAPP 是目标电压参考输入，不能与某些廉价小棒的 3.3V 电源输出混为一谈；先认清接口性质，不能统一要求“三根线”或统一把“3.3V”接上。[ST UM1075](https://www.st.com/resource/en/user_manual/um1075-stlinkv2-incircuit-debuggerprogrammer-for-stm8-and-stm32-stmicroelectronics.pdf)

## 三、USART1 通信接线

### 先接 PC 模拟上位机

```text
STM32 PA9  TX ─────→ USB-TTL RXD
STM32 PA10 RX ←───── USB-TTL TXD（实际信号必须为3.3V）
STM32 GND    ─────── USB-TTL GND
USB-TTL 5V、3.3V：不接
```

这里直接复用 USART1，不再为了调试新增 USART2。协议端口不混入任意 printf 文本；需要调试时用 SWD、OLED 或明确区分的测试固件。

没有 USB-TTL 时，可以只短接 PA9 与 PA10 做自环，并用 OLED 显示收发是否相同。自环只能检查收发路径，收发两端共用本机时钟，不能证明绝对波特率准确或与外部设备兼容。

核心板如果带外部晶体，时钟配置需匹配实际频率。HSI 也能作为 UART 时钟来源；是否可靠取决于双方时钟误差、分频和工作条件，不能写成“115200 必须有8MHz晶体，否则一定乱码”。本版优先使用已确认的板载晶体，并以外部通信测试验收。[ST AN2586](https://www.st.com/resource/en/application_note/an2586-getting-started-with-stm32f10xxx-hardware-development-stmicroelectronics.pdf)

### 再接树莓派 5

| STM32 | Pi 5 的 40 针接口 |
| --- | --- |
| PA9 TX | GPIO15 RX，物理针脚10 |
| PA10 RX | GPIO14 TX，物理针脚8 |
| GND | GND，例如物理针脚6 |

接 Pi 前拔掉 USB-TTL 的 TX/RX，不能把两个发送端并在同一根 MCU RX 线上。

Pi 5 默认主 UART 位于独立的调试串口连接器，不能直接假定 `/dev/serial0` 就是 40 针的 GPIO14/15；也不能照搬旧机型的“GPIO14/15 被蓝牙占用，必须 disable-bt”。[官方 UART 说明](https://www.raspberrypi.com/documentation/computers/configuration.html#configuring-uarts)

对支持相应 overlay 的 Raspberry Pi OS，在 `/boot/firmware/config.txt` 启用 `dtoverlay=uart0-pi5` 可将 UART0 引到 GPIO14/15；重启后检查引脚复用、实际设备节点及是否被串口登录控制台占用。以该系统随附的 overlay README 为准，不把 `uart2` 旧配置或 `/dev/serial0` 别名写死。[官方 overlay 清单](https://raw.githubusercontent.com/raspberrypi/linux/rpi-6.12.y/arch/arm/boot/dts/overlays/README)

## 四、OLED、状态灯与两键

### OLED

VCC 接 3.3V，GND 接公共地，SCL 接 PB6，SDA 接 PB7。核对模块允许的供电、上拉及控制器型号；I²C 地址常见为 0x3C/0x3D，按实物扫描和资料确认。

先显示固定文字与边框，再显示自增计数；左右偏移、缺列或黑边只能说明驱动/列映射等需要排查，不能仅凭偏移就认定 SSD1306 或 SH1106，更不能假定两者只差一个偏移常量。

### 状态灯

```text
PB8 ──220Ω──→ 绿LED阳极；绿LED阴极 → GND
PB9 ──220Ω──→ 红LED阳极；红LED阴极 → GND
```

按实际 LED 正向压降计算电流，不固定声称“每颗6mA”。状态灯以几毫安为目标；GPIO 的绝对最大电流不是正常设计工作点。

### 两键

K1 两端分别接 PB12 与 GND；K2 两端分别接 PB13 与 GND。软件配置内部上拉并防抖，按下为低，不做长按/组合键。四脚轻触按键要先用万用表确认哪两脚按下后才连通。

K2 为 STOP 操作键，软件在本地立即将 PWM 清零，再通知上位机。该软件停止不能替代针对危险负载设计的硬件急停。

## 五、照明低边驱动

面包板使用已焊转接板的 AO3400A；G/S/D 对应关系按器件数据表与转接板标注核对，不能套用 S8050 的 B/C/E。

```text
5V ──220Ω──白LED1──┐
5V ──220Ω──白LED2──┼──→ AO3400A D（漏极）
5V ──220Ω──白LED3──┘
AO3400A S（源极）────────→ GND
STM32 PA6 ──470Ω─────────→ G（栅极）
G（栅极）──100kΩ─────────→ S（源极）/ GND
```

100kΩ 下拉位于 MOSFET 的栅源之间，不放在串联电阻的 MCU 一侧来冒充同一接法。初始化时先确保关灯，再使能 PWM。

每路电流按 `(5V − LED正向压降 − MOSFET导通压降) / 220Ω` 估算，按实物核对单颗额定电流并测量总电流；本演示负载总电流保持低于100mA。万用表可测静态电流，但普通直流电压读数不能证明 PWM 频率和占空比正确，波形需示波器或逻辑分析仪验证。

占空比由上位机或 PC 脚本手动设置。上电、STOP、失联和故障均关灯，恢复通信不恢复原占空比。

本版选择白光是为了演示 RGB 补光，不把“所有外部红外光必定破坏深度”当作结论。正式成像应检查曝光、过曝、PWM 条纹和深度有效率；先以常亮光建立基线，小 LED 组不代表最终光源已经定型。[RealSense 调优说明](https://dev.realsenseai.com/docs/tuning-depth-cameras-for-best-performance/)

## 六、分步验收

| 顺序 | 检查 | 合格现象 |
| --- | --- | --- |
| 0 | 供电与下载 | 电源无短路、3.3V 符合实物规格，ST-Link 可连接与下载 |
| 1 | OLED / 状态灯 | 固定文字正常，绿/红灯可分别控制且含义一致 |
| 2 | 两键 | 快按20次计数各增加20次，无明显连发或漏触发 |
| 3 | 照明驱动 | 0%关、50%与100%有亮度差，单颗和总电流符合规格 |
| 4 | 外部 UART | PC 与 MCU 以115200 8N1连续收发测试，帧/字节计数一致、无校验错误；自环不替代此项 |
| 5 | 命令与结果 | START 等上位机确认；有效结果显示，拒绝/取消不显示旧距离；错误帧不改变输出 |
| 6 | 停止、断线与重连 | STOP 不等应答即关灯；断心跳3s关灯/红灯；重连不会恢复旧任务或旧亮度 |
| 7 | Pi / D435i 联调 | 接线、UART设备与实际成像验证通过后，再记录真实测距演示结果 |

无 Pi / D435i 时可用 PC 模拟端验证控制与显示，但不能据此声称真机测距或照明成像效果已验收。

## 七、转为插接式 PCB

沿用上述逻辑引脚；排母封装必须按实际核心板量尺寸和核对线序。为板底元件、USB 插头和 SWD 插头留空间，明确插入方向。

核心板已提供的稳压、时钟、复位和启动电路按实物使用，不在载板上重复并联一套。载板集中实现输入供电与保护、两键、状态灯、照明驱动及通信/显示连接器；删除功能不再保留整套电路。

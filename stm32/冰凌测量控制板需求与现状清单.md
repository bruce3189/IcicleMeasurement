# 冰凌测量控制板 — 需求与现状清单

> 2026-10-27 精简版。本目录四份文档共同描述第一版控制板；本文件确定功能范围，其余文件分别说明模块、物料与接线。外部旧方案仅作背景，不再作为本版的待办清单。

## 一、第一版要完成什么

完成“按键请求测量 → 上位机采集和计算 → 下位机显示状态与结果”的演示，并提供手动辅助照明控制。

- 树莓派负责 D435i、图像处理、关键点检测和测距；STM32 不重复实现这些算法。
- 采用现成 STM32F103C8T6 最小系统板，先面包板验证，后续 PCB 用排母插接核心板，并集成外围电路。
- 本目录尚无控制板业务固件；独立环境验证工程位于 `D:\STM32Workspace\environment-check`。文档中的“应实现”不代表功能已完成。

## 二、保留的需求

沿用原需求编号，便于与旧稿对照；编号有空缺不表示漏项。

| 编号 | 本版需求 | 对应模块 |
| --- | --- | --- |
| R1 | 两个独立按键：START 请求测量，STOP 请求停止 | 模块6 |
| R2 | 手动设置白光照明占空比 0–100%，默认关闭 | 模块7 |
| R4 | 绿灯表示通信正常且无故障，红灯表示失联或故障 | 模块4 |
| R6 | OLED 显示连接状态、测量状态和最近一次有效结果 | 模块2 |
| R7 | 沿用 Pi 每 500 ms 发心跳、STM32 回执的方式检测通信 | 模块1 |
| R8 | 3 s 未收到有效心跳视为失联：关灯、清除当前结果显示、红灯提示 | 模块1、2、4、7 |
| R10 | 收发测量请求、状态、结果、照明命令和故障通知 | 模块1 |
| R11 | 仅执行完整且通过校验的串口帧；不完整或错误帧不改变输出 | 模块1的软件逻辑 |
| R13 | 按键防抖，一次按下只产生一个事件，不做长按或组合键 | 模块6的软件逻辑 |

START 只发出请求，收到上位机确认的状态后才显示“测量中”。STOP 立即在本地关闭照明并发送停止请求，不依赖上位机应答；它是操作停止键，不宣称为硬件安全急停。

上位机应持续发心跳，即使没有测量任务。失联后必须重新建立通信；新会话先同步当前状态，不能因恢复心跳而恢复旧任务、旧结果或旧照明。只有收到新的有效照明命令才可重新开灯。

### 串口命令需要表达的最小语义

| 方向 | 内容 |
| --- | --- |
| STM32 → 上位机 | START、STOP 请求；心跳回执 |
| 上位机 → STM32 | 连接心跳、当前测量状态、有效结果或拒绝/取消状态、故障通知、`LIGHT_SET` 的 0–100 占空比参数 |

`LIGHT_ON/OFF` 只有开关语义，不能代替亮度参数。上表规定的是功能语义，完整帧封装、字段和校验算法仍需在两端实现前统一，不把现有 `$HB/$AK` 示例当成完整协议。收到拒绝、取消或新任务状态时，不能把上一轮距离继续显示为本轮结果。

## 三、删除的功能及原因

| 原需求/模块 | 本版处理 | 原因 |
| --- | --- | --- |
| R3、R12 / 模块3：光敏电阻与自动调光 | 不接入、不列入验收 | 尚无环境光读数与关键点效果的验证；自动变光还会增加成像变化 |
| R5 / 模块5：蜂鸣器 | 删除 | OLED 与双色状态灯已能反馈状态，先减少器件与驱动 |
| R9 / 模块8：树莓派硬复位、拨码使能 | 删除，不接电源按钮或所谓 RUN 触点 | 与测量功能无直接关系，误操作会中断系统；旧板 RUN 接法不能直接套到 Pi 5 |
| R8 中的 10 s 动作、故障码写 Flash | 删除 | 不需要持久故障日志，也不需要第二级自动复位 |
| R15：板温；R6 中的 IP 显示 | 删除 | 不参与测距，且温度来源、网络依赖均未落实 |
| R14：独立 ESTOP 键与命令 | 删除 | 本装置没有已定义的危险执行机构；保留 STOP 本地关灯即可 |
| R13 中的长按识别 | 删除 | 两键已覆盖当前操作 |
| 第二路调试串口、光敏 DO、预留复位口 | 不作为第一版接口 | 当前可复用 USART1 接 PC 或树莓派，调试用 SWD/OLED |

已有但未采用的器件保留实物，不需要为了使用已有模块而增加功能。后续如新增电机或其他危险负载，应另行设计相应的停止与保护电路。

## 四、现状与真正待确认项

以下物料状态来自原文件记录，本轮未现场清点：已有最小系统板、ST-Link、面包板/杜邦线、0.96 英寸 OLED、光敏电阻模块；USB-TTL、树莓派和 D435i 原记录为缺少，其他物料待清点。光敏模块不再是本版必需品。

| 待确认项 | 何时需要确定 |
| --- | --- |
| 最小系统板的准确版本、排针顺序、尺寸、USB/5V 电源连通关系 | 接线与绘制载板封装前 |
| OLED 控制器、工作电压、I²C 地址及板载上拉 | 点屏前；不能仅凭尺寸或 `JMD0.96D-1` 丝印认定控制器 |
| 工具链和底层库 | 已确定 STM32CubeIDE + STM32CubeF1 HAL（HAL1）；命令行编译已通过，图形工具安装待完成，见《开发环境说明.md》 |
| 串口完整协议、PC 最小收发程序 | 两端驱动联调前 |
| 树莓派 OS 版本、启用的 UART 和实际设备节点 | 接树莓派前 |
| 最终光源电流、安装方式、核心板插拔和 USB/SWD 访问空间 | 正式 PCB 定板前 |

本版不引入电池供电、自动重启、网络显示或更换屏幕尺寸等额外待办。

## 五、实施与验收顺序

1. 清点保留功能需要的物料，确认电源与下载器接口；跑通下载和板载点灯。
2. 点亮 OLED，再验证双 LED、两键和低功率照明驱动。
3. 没有 USB-TTL 时可做 USART1 自环，只验证收发路径；补齐外部串口设备后测试实际 115200 8N1 通信。
4. 使用 PC 模拟上位机，验证 START/STOP、结果显示、亮度参数、校验失败丢弃和 3 s 失联关灯。
5. 接入树莓派与 D435i，检查照明对 RGB/深度的实际影响，再完成载板原理图、布局、打样和整机联调。

交付物为外围控制板原理图、PCB/BOM、固件与上位机收发程序、实物及测试记录。核心模块采用现成板时，在论文中明确标注其来源与自研边界。

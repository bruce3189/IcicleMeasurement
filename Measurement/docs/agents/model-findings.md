# 附录 B · 模型实验与结论

> 历史三点 Pose 实验资料，未用于评价当前选定的两点模型。当前版本见 [最终成果](../../../final_results/README.md)；这些旧实验的本项目副本现位于 `history_archive/yolov11_legacy/runs_pose/`。下文原始路径与统计保留作历史证据。

> 本文件的目的不是记录"我们训过什么"，而是**列出哪些路已经走死了，避免重复劳动**。
> 所有指标来自 `D:\yolov11\runs_pose\` 下各实验的 `results.csv` 与像素级评估 `summary.json`；诊断结论来自 `codex_review_20261022\诊断报告.md` 与 `tip_refine_232\可疑框复检\复检说明.txt`。

## 0. 一句话结论

**当前 pose 模型的 tip 定位能力，不如一个完全不懂关键点的固定规则。** 在你改变评估指标或者换任务定义之前，任何"再训一轮会更好"的假设都没有依据。

## 1. 三个必须先知道的结论

### 结论 A：模型比瞎猜还差

在 val 38 张（286 个 GT 框）上，模型预测的 tip 误差中位 **54.9 px**；

而一个零学习基线——"把 tip 放在框底中点，再往上偏移 25 px"——误差是 **34 px**。

模型比固定规则差 1.6 倍。它学到的不是"尖端在哪"，而是"框大概长什么样"。

### 结论 B：高 mAP 是评估口径造成的假象

`ice80_yolo26` 的 Pose mAP50 = 0.97633 看着很好，但这是默认参数导致的：

数据配置没提供 `kpt_oks_sigmas`，本地 ultralytics 对非 COCO 的三关键点用了默认 `[1/3, 1/3, 1/3]`，OKS 在可见点之间平均。**两个根部点准，就能把尖端完全失败掩盖掉。**

复算证据：21 个 tip 误差 >10% 框高的匹配实例，整体 OKS 仍然全部 >0.5；`001_00047` 里四根长冰凌 tip 误差达框高的 44.5%–53.1%，整体 OKS 仍约 0.69。

### 结论 C：这是任务定义问题，不是模型容量问题

tip 在标注里是 1–2 px 的镜面高光。图片 6.31 MP，训练 `imgsz=1280` 时整图被缩小约 3 倍，**tip 缩到 0.3–0.7 px，也就是亚像素**。

模型看不到一个稳定存在的目标，只能回归到"框内某个固定相对位置"——实测预测的横向位置恒为 **0.51 框宽**，真值分布是 **0.37±0.23**。

因此：加数据、加权重、提分辨率都改变不了这一点。

## 3. `ice80_yolo26` 的三个问题

### 3.1 指标失真

见结论 B。`kpt_oks_sigmas` 未设置，三关键点用默认值，根部点掩盖尖端失败。

### 3.2 数据泄漏

Easy80 按视频名前缀抽帧，train / val / test 里混有同一视频的相邻帧。例如 train 有 `004_00034`、val 有 `004_00035`。

后果：val / test 指标对新场景系统性偏乐观。任何基于这批指标的"模型泛化能力"结论都不成立。

（这也正是后续 `tip_refine_232` 改成「按同批连续帧 4 张一块整块划分」的原因。）

### 3.3 长目标系统性失败

同一个 `best.pt`，不同输入分辨率的独立复算（test 10 图 72 框，conf 0.25）：

| 指标 | 640 | 1280 | 1536 |
|---|---:|---:|---:|
| 输出框数 | 107 | 83 | 75 |
| 匹配框（IoU≥0.5） | 61 | 72 | 72 |
| 框 IoU 中位 | 0.785 | 0.866 | 0.867 |
| tip 误差中位 (px) | 182.5 | 53.0 | 46.3 |
| tip 误差 P90 (px) | 263.9 | 163.6 | 240.9 |
| tip PCK@10% 框高 | 18.8% | 65.3% | 70.8% |

长目标（>1200 px）在 1536 下 7 个样本的 tip 中位误差约 **842 px**。即便用完整的规则修正（`tip.x = 两 base.x 均值`、`tip.y = 框底 − 0.04×框高`），仍剩约 **445 px**（1280 下 690 → 313 px）。

训练集自己也没拟合好：≥1200 px 的 52 个框，tip 中位误差 281.8 px（相对框高 20.6%）。

## 4. `tip_refine_232`：tip 加权实验（已做过，无效）

数据：232 张（169/38/25），1633 框，三点齐 1139，无关键点的框已剔除。
像素级评估：38 图 286 GT，`imgsz 1280`、`conf 0.25`、NMS IoU 0.7、匹配 IoU 0.5。

| 指标 | tip3（逐点加权） | control_tip1（等权） | 判定 |
|---|---:|---:|---|
| 匹配 GT / 输出框 | 262 / 297 | 262 / 294 | 打平 |
| 漏检 / 多余框 | 24 / 35 | 24 / 32 | 加权多 3 个多余框 |
| 框 IoU 中位 / P90 | 0.8386 / 0.9205 | 0.8424 / 0.9223 | 加权略低 |
| 框底误差中位 / P90 (px) | 18.90 / 72.53 | 21.20 / 81.75 | 加权略好 |
| **tip 中位误差 (px)** | **67.74** | **67.12** | **加权反而差 0.62 px** |
| tip P90 (px) | 196.58 | 172.25 | 加权差 24 px |
| tip PCK@5% / @10%（匹配内） | 27.59% / 60.92% | 24.90% / 60.54% | 持平 |
| tip_success10_all_gt | 55.79% | 55.44% | 差 0.35 pt |
| **tip 出框率** | **24.24%** | **31.97%** | **加权改善 7.7 pt** |
| base_left PCK@10% | 92.74% | 94.44% | 加权退步 |
| base_right PCK@10% | 100.0% | 98.62% | 加权略好 |
| ≥1200 px 长目标 tip 中位 | 216.52（n=25） | 201.36（n=25） | 加权更差 15 px |
| 700–1200 px tip 中位 | 65.34（n=172） | 66.15（n=173） | 持平 |

**怎么读这张表**：

- ✅ 加权确实生效了（RLE/OKS 两项同时加权、one2many/one2one 双分支）
- ✅ 唯一实在的收益：tip 跑到框外的比例从 32% 降到 24%
- ❌ tip 定位精度**没有改善**，中位误差和 P90 都变差了
- ❌ mAP 两项都略低，不能用 mAP 说加权有效

结论：**tip 加权解决不了 tip 定位问题。**

## 5. 误差分布（为什么"看起来还行"是错觉）

270 个匹配框里，tip 误差分布：

| 误差区间 | 占比 |
|---|---|
| ≤20 px | 11% |
| 20–50 px | 34% |
| 50–100 px | 29% |
| 100–200 px | 14% |
| **>200 px** | **12%** |

那 12% 的 tip 落在框高 0.5 附近——它们根本不是尖端，而是框中间。

同时被复核纠正的两条几何事实：

- 框普遍比冰凌宽近一倍：base 两点间距中位 69 px，只有框宽的 53%
- tip 是 1–2 px 的镜面高光（见结论 C）

## 6. 已证伪的方向（不要再试）

| 方向 | 结论 | 证据 |
|---|---|---|
| tip 逐点加权损失 | **无效** | tip 中位 67.74 vs 67.12，P90 恶化 |
| 100 轮 tip 加权（`ice80_yolo26_tipw`） | **明显更差** | Pose mAP50-95 0.79008 → 0.70419；`train/rle_loss` 3.84 → 10.53 |
| 提高输入分辨率 | **部分改善但不够** | 640→1536 tip 中位 182.5→46.3 px，长目标仍 842 px |
| 冻结骨干只训 head | **无改善** | 三个 head 实验 Box 指标完全相同 |
| 2e-4 学习率微调 | **伤 tip** | 232 张上 54.9 → 67 px 量级 |
| 用 mAP 判断关键点好坏 | **方法错误** | 见结论 B |
| 靠"再训一轮"碰运气 | **已多次否定** | 上表五行都是这个思路的变体 |

## 7. 值得试的方向（尚未执行）

1. **换评估指标**：`kpt_oks_sigmas` 显式设置，或干脆用「tip 单独误差 + 误差>100px 的比例」作为唯一验收口径。当前 >100 px 占 26%。
2. **改任务定义**：既然零学习基线（框底中点 −25 px）就是 34 px，可以先彻底放弃 tip 回归，只用框 + 规则定位 tip，把精力放到框精度和深度上。
3. **只修最差样本**：先处理最差的 120 个框，验收看「误差 >100 px 的比例」而不是 mAP。
4. **按拍摄来源隔离验证集**：消除相邻帧泄漏，否则所有指标都不可信。
5. **一次只改一个因素做小规模对照**，不再盲跑同配置 100 轮。

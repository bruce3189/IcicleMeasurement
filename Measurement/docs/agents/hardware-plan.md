## 1. 三层分工

```
树莓派 5（上位机 / 主控）
  ├─ D435i 走 USB 3.0 直连（视频与深度不经过 STM32）
  ├─ 跑 YOLO pose 推理 + 端点测距算法 + 界面
  └─ 决定采集与推理流程
        ↕ UART（3.3V，双向）
STM32 控制板（下位机 / 执行与交互）
  ├─ 按键：触发测量、停止、急停
  ├─ 状态灯 / 蜂鸣：运行、故障、失联
  ├─ OLED：显示 Pi 状态、IP、模式、结果、错误码
  ├─ PWM：辅助照明亮度（经驱动器件，不由 MCU 引脚直接承担电流）
  ├─ I²C：BH1750 环境光
  └─ 看门狗：心跳超时判定 + 可选硬复位 Pi
```

**职责边界**：STM32 不承担图像处理和体积计算。树莓派也不直接驱动机器件。

## 2. 树莓派 5 的三个硬约束

这三条踩错会直接导致"接上不亮"或"通信不通"：

| 约束 | 事实 | 后果 |
|---|---|---|
| USB-C 不支持显示 | Pi5 的 USB-C **只供电**，不支持 DP Alt Mode。官方文档原话："No Raspberry Pi models support video over USB-C" | 任何「USB-C 一线通」便携屏接 Pi5 都点不亮，必须走 micro-HDMI |
| USB-C 不输出视频 | 同上 | 不要尝试 HDMI→USB-C 转接线的方案 |
| GPIO14/15 默认归蓝牙 | 这两根就是 UART0 的 TXD/RXD，默认被板载蓝牙占用 | 直接接 STM32 无法通信，需释放或换 UART |

### 2.1 UART 引脚冲突的两个改法

```ini
# /boot/firmware/config.txt

# 改法 A：把 14/15 让给 STM32，代价是失去串口 console
dtoverlay=disable-bt

# 改法 B（推荐）：14/15 留作调试 console，STM32 走另一路 UART
dtoverlay=uart2          # 引到 GPIO0/1 等，具体映射查官方文档
```

推荐 B 的理由：无屏部署时，**串口 console 是最后的救援通道**。一根 USB-TTL 线插电脑就能登录系统，比拆机接 HDMI 现实得多。多花两根线换这条后路是值得的。

### 2.2 音频

**Pi5 取消了 3.5mm 耳机孔**（Pi4 有）。出声只能走 HDMI、USB 或蓝牙。所以便携屏带喇叭有实际价值。

### 2.3 供电

| 项 | 要求 |
|---|---|
| Pi5 电源 | 官方 27W USB-C（5V/5A）。用 5V/3A 时外设总电流被限制在 600mA |
| 便携屏 | **必须独立供电**，15.6" 屏通常 5V/2A 以上，不能从 Pi 的 USB 口取电 |
| 控制板 | 可从 Pi 40 针的 5V 引脚取电，经保险丝后只供 MCU、指示灯、按键等低功耗电路 |

## 3. STM32 控制板元件清单

主控：**STM32F103C8T6，LQFP48**（低速控制 + UART，不做视觉计算）

| 类别 | 元件 | 备注 |
|---|---|---|
| 时钟 | 8 MHz 晶体 ×1 + 匹配负载电容 ×2 | 电容值按晶体数据手册算；**不能省**，见 §3.1 |
| 电源 | 5V 输入、500mA 自恢复保险丝 ×1、3.3V LDO ×1（如 AP2112K-3.3）、输入/输出储能电容各 ×1、每组电源脚 100nF 去耦 | 从 Pi 取电，保险丝保护 Pi |
| 启动复位 | BOOT0 下拉 10kΩ ×1、NRST 上拉 10kΩ ×1、复位按键 ×1 | BOOT0 不能悬空 |
| 调试 | SWD 4 针（SWDIO / SWCLK / GND / 3V3） | 外接 ST-Link 下载调试 |
| 通信 | 树莓派串口 4 针（5V / GND / MCU_TX / MCU_RX），预留串联电阻焊盘 | 两端都是 3.3V 逻辑，**不要把 5V 信号接到 Pi GPIO** |
| 人机接口 | 状态 LED ×2 + 限流电阻 ×2、功能按键 1–2 只、端子/插座 | 按机壳和线束选型 |
| 照明驱动 | PWM 输出 + 驱动器件（MOS/三极管） | 光源电流不直接由 MCU 引脚承担 |
| 传感器/显示 | BH1750（I²C）+ OLED（I²C），含上拉电阻 | 1.3" 128×64 |

元件总数约 25–30 个，双层板，单面布局。

### 3.1 两个不能省的元件

**8MHz 晶体**：F103 内部有 8MHz RC（HSI），看起来能省。但 HSI 全温区精度 ±1%–2%，而 UART 异步通信靠双方波特率匹配，累积误差超过约 3% 就会丢帧。要和 Pi 跑 115200 的协议帧，内部 RC 属于"能通但不保证"，出问题是偶发乱码，极难排查。为一颗几毛钱的晶体赌这个不值得。

**BOOT0 下拉电阻**：不能悬空。悬空或拉高会进系统存储器启动模式，程序不跑；复位瞬间引脚浮动还会导致"偶尔上电不启动"，这类故障最难查。

### 3.2 可以省的

**电源开关**。5V 从 Pi 的 40 针取，Pi 断电就全断，加开关是多余的。

## 4. 引脚分配与协议

### 4.1 串口连接（按改法 A；改法 B 时换成对应 GPIO）

| 树莓派 5 | 物理针脚 | STM32 |
|---|---|---|
| GPIO14 / TXD | 8 | USART1_RX（PA10） |
| GPIO15 / RXD | 10 | USART1_TX（PA9） |
| GND | 6 | GND |

### 4.2 协议分层

原方案只写了「命令类型、参数、校验和」，实际应按方向分三层：

| 层 | 方向 | 内容 |
|---|---|---|
| 触发 | STM32 → Pi | `START` / `STOP` / `ESTOP`。急停不等 Pi 应答，直接切断辅助照明 |
| 执行 | Pi → STM32 | `LIGHT_ON/OFF` / `SHOW_RESULT` / `FAULT` |
| 监督 | 双向心跳 | Pi 每 500ms 发心跳，STM32 回执 |

### 4.3 心跳帧格式（建议）

```
Pi  → STM32   $HB,<seq>,<状态码>*<校验>     每 500 ms
STM32 → Pi    $AK,<seq>*<校验>              收到即回
```

### 4.4 心跳超时响应

| 条件 | 动作 |
|---|---|
| 连续 3s 无心跳 | 状态灯转红 + 短鸣，OLED 首行改 `PI LOST`，串口继续监听 |
| 连续 10s 无心跳 | 故障码写 Flash；若允许自动恢复，拉低 Pi 的 RUN 触点硬复位 |
| 恢复收到 | 清故障标志，灯回绿 |

**硬复位要设开关**：复位会丢失正在测的数据。用拨码开关或长按 5 秒使能，不要默认打开。Pi5 的 RUN 触点位置以实物丝印为准，接线前用万用表确认。

## 5. 无屏部署（OLED 显示设计）

1.3" OLED 只有 128×64，四行 × 十六字符，必须按信息价值排序：

```
L1  PI OK    10.0.0.23     心跳状态 + IP（最重要：判断活着没、怎么连）
L2  MODE  READY            待机 / 测量中 / 错误
L3  L=42.7mm  T=38C        最近一次结果 + 板温
L4  ERR  none              最近错误码
```

**定位**：它是「树莓派的代理显示屏」，不是 STM32 自己的调试屏。

## 6. 故障恢复优先级

按代价从低到高，不要一上来就硬复位：

| 级别 | 手段 |
|---|---|
| 进程级 | systemd `Restart=always` + `WatchdogSec=30`，程序卡死由系统重启 |
| 通信级 | Pi 侧检测串口断开后重开设备节点，进程不退出；重连后重新握手 |
| 整机级 | STM32 拉低 RUN 触点复位 Pi |
| 人工级 | USB-TTL 接调试串口，或临时接 HDMI + 键鼠 |

## 7. PCB 状态与打样路径

**当前状态：方案与元件清单已定，原理图未完成，PCB 未画、未打样。**

计划是在同一个立创 EDA 工程里做五个功能模块，最后打样一块双层板（不是五块板）：

1. STM32F103C8T6 最小系统
2. 电源输入、稳压与保护
3. UART 通信及测量按键
4. PWM 辅助照明驱动
5. I²C 传感器与 OLED 接口

### 7.1 设计顺序

先画完整的最小系统 → 再并入电源保护、UART、按键、PWM、BH1750、OLED → 统一分配引脚、查网络和封装 → 生成一块 PCB。不需要先做独立最小系统板再做扩展板。

### 7.2 打样与代焊

**方案一：嘉立创 SMT 经济型**（推荐，因为图就是在立创 EDA 画的，BOM 与坐标自动带）

- 工程费 50 元/订单（含钢网），贴片约 0.01 元/点
- 只做单面贴片，不贴插件（排针、端子、按键、OLED 座要自己焊）
- LQFP48 是 0.5mm 间距，经济型下限 0.4mm，**能贴**
- **换料费是最大的隐形费用**：扩展库物料约 20 元/料号。下单前把 BOM 里能换基础库的换掉，阻容统一成一种规格，接插件选"不贴"

**方案二：标准型**（工程费 150 元/面，双面 300 元）——需要双面贴或波峰焊插件时才用

**方案三：淘宝代焊**（手贴 0.3 元/焊盘 + 钢网 100–150 元）——客供料、就做 1–2 片时用

### 7.3 一个更省事的第一版方案

如果只是验证，可以**不在板上放 MCU**，改放两排 2.54mm 排母，直接插一块现成的 STM32F103C8T6 最小系统板（约 15–25 元）。

- 好处：不用碰 0.5mm 焊盘，不用 SMT，改设计只要换一块 20 元的模块
- 代价：体积大一圈（最小系统板约 53×22mm），LED/按键会和板上重复

## 8. 上电与验收顺序

```
1. 焊完先不插 MCU，测 5V 和 3.3V 对地电阻，确认无短路
2. 上电测 3.3V 是否在 3.2–3.4V，LDO 有没有发烫
3. 插 MCU，用 ST-Link 下载 LED/按键程序，验证复位、SWD、串口收发
4. 再接树莓派与 D435i 做整机联调
```

SMT 出来先看 LQFP48 四边引脚有没有相邻连锡（0.5mm 间距最常见的故障），厂里通常只做目检。

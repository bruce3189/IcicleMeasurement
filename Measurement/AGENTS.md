## 一句话

RGB-D 拍冰凌 → 检出每根冰凌的框 + 两个关键点（`tip` 下端尖端 / `base` 上端根部中点）→ 深度反投影求端点 XYZ → 算欧氏距离。终点形态：树莓派 5 + D435i + 自绘 STM32 控制板。

技术栈：Python 3.9+ / **PyQt5** / numpy / opencv-python。没有 PySide6、Open3D、PyVista。

## 八条红线

违反这些**不会报错、测试也抓不住**，只体现在结果数值上。

1. **几何比例只允许一处**：`geometry.build_cloud` 的单一等比系数。禁止任何 Z 方向额外压缩/放大或第二套 X/Y 系数 —— 曾有双套比例导致 Z 失真 200 倍（显示 −1.028，真实 −0.00525 m）。
2. **类别只许着色**：不许参与抽稀、聚焦半径、任何筛选。验收标准是"改类别后坐标差恒为 0"。
3. **`core.py` / `evidence.py` / `geometry.py` 零 Qt 依赖**：界面问题只在 `gui.py` 与 `ui/` 内解决。
4. **不为 UI 手感改算法阈值**：窗口序列（3→60 px）、六项证据闸门、0.8 稳定性阈值都被 benchmark 和 101 个用例锁着。
5. **不拿 mAP 当关键点可用性的证据**：`kpt_oks_sigmas` 默认值会让两个根部点掩盖尖端完全失败。
6. **不校验路径不许开训**：当前两点数据在 `final_results/training/dataset/`，旧配置中的桌面绝对路径可能失效；先核实实际数据与划分。
7. **绘制循环内不复用外层变量名**：`visible` 曾覆盖 numpy 掩膜，导致点云整块消失且几乎无报错。
8. **不移除裁剪窗口去重逻辑**：重复窗口重复计分能凭空凑出"连续通过"，让证据不足的端点被接受。

## 历史状态快照（三点 Pose，非当前最终模型）

| 层 | 状态 | 关键事实 |
|---|---|---|
| 软件 | ✅ 可用 | 101 个 unittest 全绿；benchmark 30/30；端点误差 0.6165 mm |
| 数据 | ⚠ 标注不齐 | 400 张已标 242、入库 232、**158 张未标**；yaml 路径失效 |
| 模型 | ❌ **不达标** | tip 误差中位 54.9 px，**不如零学习基线 34 px** |
| 硬件 | ⚠ 未打样 | 元件清单与引脚已定，原理图未完成 |

**精度口径**：`0.6165 mm` 是**合成数据**结果，只验证软件流程。真实透明冰凌从未做过带真值验证 —— 不要对外说成实测精度。

**模型为什么会这样**：tip 是 1–2 px 镜面高光，缩到 `imgsz=1280` 后只剩 0.3–0.7 px（亚像素），模型只能回归到"框内固定相对位置"。**这是任务定义问题，不是容量问题** —— 加数据、加权重、提分辨率三条都已证伪。
